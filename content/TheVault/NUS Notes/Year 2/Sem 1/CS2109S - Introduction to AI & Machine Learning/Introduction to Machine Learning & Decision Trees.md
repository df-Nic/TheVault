# Machine Learning
---
In <span style='color:var(--mk-color-turquoise)'>machine learning</span>, the environment is <span style='color:var(--mk-color-yellow)'>mostly episodic</span>.

Therefore what is the <span style='color:var(--mk-color-orange)'>difference</span> between AI and ML? Unlike AI, ML has the <span style='color:var(--mk-color-yellow)'>ability to learn</span> without external help or in other words **improves with experience**.

**Why machine learning**
- Can recognise images
- Generative models
- Image generation
- Games (Find the best move)
## Types of Feedback

There are <span style='color:var(--mk-color-orange)'>3 types of feedback</span>:
1) **Supervised**
> There is some form of <span style='color:var(--mk-color-yellow)'>direct supervision</span> where a person **tells the machine** weather its output is correct or not.
2) **Unsupervised**
> There is <span style='color:var(--mk-color-red)'>no supervision</span> and the machine will own self find some meaning or patterns from the input.
3) **Reinforcement**
> It is like trial an error, where the **machine will just do something** but the <span style='color:var(--mk-color-yellow)'>environment will give a feedback</span> (*reward*). Essentially there is a **reward function** in its feedback loop.

> [!note] Semi/Weakly Supervised
> It is an <span style='color:var(--mk-color-yellow)'>inbetween</span> for both supervised and unsupervised. 
> 
> Where some of its outputs might have feedback (*Supervised*) while some is not (*Unsupervised*).
## Supervised Learning

Essentially there <span style='color:var(--mk-color-green)'>will always be a right answer</span> ($y$) given any input ($x$). Essentially like our **training dataset**, which has inputs and an output (*The thing we want to predict*).

> [!info] Types of Supervised Learning
> There are <span style='color:var(--mk-color-orange)'>2 types</span> of supervised learning:
> 1) **Regression** - Predict <b><mark style='background:var(--mk-color-yellow)'>continuous</mark></b> outputs.
> 2) **Classification** - Predicts <b><mark style='background:var(--mk-color-yellow)'>discrete</mark></b> outputs (*Grouping*).

In a **formal definition**, assume that $y$ is **generated by a real mapping function**, $f : x \rightarrow y$.

We will like to find a <span style='color:var(--mk-color-turquoise)'>hypothesis</span> $h$ such that $h : x \rightarrow \hat{y}$ from a<span style='color:var(--mk-color-turquoise)'> hypothesis class</span> $H$, such that $h \approx f$ given a **training set**.

A <span style='color:var(--mk-color-turquoise)'>hypothesis</span>, is a <span style='color:var(--mk-color-yellow)'>machine learning model</span> and the <span style='color:var(--mk-color-turquoise)'>hypothesis class</span> is just a **set of machine learning models**.

Thus we are using a **learning algorithm** to <span style='color:var(--mk-color-yellow)'>find a hypothesis</span> such that its predictions closely matches the real outputs.

### Performance Measure

But <span style='color:var(--mk-color-orange)'>just how good is the hypothesis chosen</span> is compared to the real mapping function? There are a few ways to determine:
- Use **theorems** from statistical learning theory
- Use a **testing set** to <span style='color:var(--mk-color-yellow)'>test the hypothesis</span> on a new set of examples

In practice, a <span style='color:var(--mk-color-yellow)'>dataset given will be spilt into 2</span> sections a **training set** and a **testing set**.

But how do we evaluate how good this function is.
#### Regression Models

**Error**
>The error is defined as the <span style='color:var(--mk-color-yellow)'>difference between predicted and actual</span> values.

The formula is as such:
- **Absolute error** - $\vert \hat{y} - y \vert$
- **Square error** - $(\hat{y} - y)^{2}$

However this will only be <span style='color:var(--mk-color-green)'>better</span> if there is <b><mark style='background:var(--mk-color-yellow)'>only 1 sample</mark></b>.

For **multiple samples**, <span style='color:var(--mk-color-yellow)'>take the mean</span> of the errors
$$
\text{Mean Squared Error} = \frac{1}{N} \sum^{N}_{i = i} (\hat{y_{i}} - y_{i})^{2}
$$

$$
\text{Mean Absolute Error} = \frac{1}{N} \sum^{N}_{i = i} \vert\hat{y_{i}} - y_{i}\vert
$$
#### Classification Models

**Correctness & Accuracy**
> It is when the model <span style='color:var(--mk-color-green)'>correctly predict the true label</span>.

To <span style='color:var(--mk-color-orange)'>compute</span> **correctness or accuracy** as follows:
$$
\frac{1}{N} \sum^{N}_{i = 1} \hat{y_{i}} =y_{i}
$$
If $\hat{y_{i}} = y_{i}$ then the value will be 1, otherwise it will be 0.

**Confusion Matrix**
> A <span style='color:var(--mk-color-yellow)'>grouping of the classifications</span> based on the true label

> [!important] Important Formulas
> **Accuracy** = $\frac{TP + TN}{TP + FN + FP + TN}$
> 
> **Precision** = $\frac{TP}{TP + FP}$
> 
> **Recall** = $\frac{TP}{TP + FN}$
> 
> **F1 Score** = $\frac{2}{\frac{1}{P} + \frac{1}{R}}$

# Decision Tree
---
A decision tree is one of the many <span style='color:var(--mk-color-yellow)'>representation of a hypothesis</span>. It is able to <b><mark style='background:var(--mk-color-yellow)'>express any function</mark></b> of input **attributes** (*It is like a hypothesis class*). But it is <span style='color:var(--mk-color-red)'>not possible to find a tree that perfectly label each data row</span> (*Inconsistent data*).

Think of it like this for **every attribute there will be a decision made** and at every level of the tree there will be an attribute to make a decision on until the **leaf node is reached which will be the actual prediction**.

<span style='color:var(--mk-color-red)'>Dealing with continuous values</span> can be problematic because this will cause **unnecessary branching**. One way to deal with this is to <span style='color:var(--mk-color-yellow)'>partition the values into bins</span>.

What about <span style='color:var(--mk-color-red)'>missing values</span>. There are many ways to deal with this:
- **Assign most common attribute**
- **Average**
- **Highest probability value**
- **Drop row/attribute**
## Decision Tree Learning

It is a <span style='color:var(--mk-color-yellow)'>greedy, top-down</span>, recursive algorithm to <span style='color:var(--mk-color-orange)'>construct a decision tree</span>.

> [!tldr] Tldr DLT
> Check the data given first, there will be 3 possibilities:
> - **Empty dataset**, in which just <span style='color:var(--mk-color-yellow)'>return the default value</span>
> - **Same Y value**, just return Y
> - There are <span style='color:var(--mk-color-red)'>no attributes</span>, then return the mode of the output variable
> 
> Else, we will build the decision tree starting with the <span style='color:var(--mk-color-yellow)'>best attribute</span> defined by `choose_attriute()`.
> 
> Afterwards **spilt the dataset** based on the **unique values of the best attribute**.
> 
> Then recursively build the subtree with the spilt dataset.

Be careful of <span style='color:var(--mk-color-red)'>overfitting</span> which **captures** data perfectly including <span style='color:var(--mk-color-yellow)'>noise</span>
> **Performance** of the decision tree is <span style='color:var(--mk-color-yellow)'>perfect on the training data</span>. But is <span style='color:var(--mk-color-red)'>bad on the test data</span>
### Choosing an Attribute

The goal of <span style='color:var(--mk-color-orange)'>choosing an attribute</span>, is to find 1 that can **spilt the data** such that for each unique value, <span style='color:var(--mk-color-yellow)'>it can be all positive or all negative</span>.

### Evaluating an Attribute

**Entropy**
>It is the **measure of randomness**

To <span style='color:var(--mk-color-orange)'>calculate</span> entropy:
$$
I(P(v_{1}), \dots,P(v_{n})) = -\sum^{n}_{i = 1} P(v_{i})log_{2}P(v_{i})
$$
**Where:**
- $P(v_{i})$ is the <span style='color:var(--mk-color-yellow)'>probability of this value</span> appearing in the dataset.

The **higher the entropy**, the <b><span style='color: var(--mk-color-red)'>more random the data is</span></b> (*50 50*).

**Information Gain**
> It is just a <span style='color:var(--mk-color-yellow)'>measurement</span> of how much **information is gained from this attribute**

It is the **entropy** of the dataset <span style='color:var(--mk-color-yellow)'>before splitting</span> into the respective unique values (*Children nodes*) **minus** the total entropy of <span style='color:var(--mk-color-yellow)'>all the children</span>.

<b><mark style='background:var(--mk-color-orange)'>Remember</mark></b> to **times the probability of the label to the entropy**.

### Pruning

It is more preferable for the decision tree to be **short/simple**, since it will be <span style='color:var(--mk-color-green)'>unlikely to be a coincidence</span> that the hypothesis fits the data (*Occam's Razor*). This results in an <span style='color:var(--mk-color-green)'>increase in accuracy</span>.

There are <span style='color:var(--mk-color-orange)'>2 ways to prune</span>:
1) By setting the **minimum number of samples** in the leaves
2) Setting a **maximum depth**

**Example:**
![[Pruning Decision Tree Example.png|center]]

When we prune, we will **combine the samples** into 1 and <span style='color:var(--mk-color-yellow)'>take the majority</span>.

Take a look at the right tree, at the leaf, there is a total of <span style='color:var(--mk-color-green)'>1 T</span> and <span style='color:var(--mk-color-red)'>2 F</span>, for a majority of <span style='color:var(--mk-color-red)'>F</span>. Afterwards condition 4 is pruned. 

**However**, at condition 3, **be it yes or no the decision is false** thus it can be <span style='color:var(--mk-color-yellow)'>pruned further</span> since condition 3 is not needed. This will **continue until condition 1**.
